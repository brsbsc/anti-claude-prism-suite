# Prism 跨厂商模型会诊与两轮对抗辩论协议

本技能依托 `prism-files_files` MCP 服务提供的 `prism_list_models` 与 `prism_ask_model` 工具，在不消耗当前主会话额度的前提下，对复杂工程决策与代码变更实施跨模型家族审查与对抗收敛。

## 1. 触发门槛与四级能力梯队

发起外部会诊前，先调用 `prism_list_models` 查看当前网关已配置的实时可用模型清单，按任务风险与复杂度严格匹配梯队：

- **T1 顶配旗舰（重决策 / 架构拍板 / 两轮对抗辩论）**
  - 适用：跨模块架构重构、安全/凭据/沙箱/代理核心链路变更、不可逆数据迁移、多候选方案各有硬伤需审慎定夺。
  - 禁止：严禁用 T1 处理日常长文摘要、格式整理或轻微单点修复。
- **T2 常规主力（日常代码 Diff 交叉二审 / 第二意见）**
  - 适用：常规功能 PR 或多文件 Diff 审查、边界条件漏检排查、中等复杂度实现方案复核与疑难报错定位。
- **T3 / T4 进阶性价比与轻量高速（高频梳理 / 长文摘要）**
  - 适用：长日志或长规范归纳、中文文档提炼、批量低难度初筛，以及 T1/T2 触发限流时的降级备选。

## 2. 跨厂商避让铁律（严禁同家族自审）

模型同源盲区会导致同类隐性缺陷漏检，选择目标模型时必须避开当前主控所属厂商：

- 当前主控属于 **Claude** 家族 → 外部会诊必须从同梯队的 **OpenAI / Gemini**（或异构第三方家族）中选择；
- 当前主控属于 **Gemini** 家族 → 外部会诊必须从同梯队的 **Claude / OpenAI** 中选择；
- 当前主控属于 **OpenAI / GPT** 家族 → 外部会诊必须从同梯队的 **Claude / Gemini** 中选择；
- **极高风险双审**：涉及凭据安全、底层进程控制或生产关键链路时，可同时征询与主控不同的两家 T1 模型，形成三厂商交叉闭环；
- **限流平滑降级**：若 `prism_ask_model` 返回 `429` 或线路超时，立即依据 `prism_list_models` 切换同梯队备用线路或另一跨厂商模型，不原地盲目重试。

## 3. 高风险决策：两轮对抗辩论协议（Adversarial Debate）

当面对重大架构分歧或高风险改造成本时，按以下标准三阶段执行收敛：

### 阶段一：独立对立立论（正方提案 vs 反方挑刺）

外部网关模型无本地文件系统访问权限且看不到当前会话上下文，必须先整理一份**完全脱敏**的统一问题背景包（业务目标、硬性约束、候选方案摘要、关键接口/代码片段），并行调用两个异构 T1 模型的 `prism_ask_model`：

1. **正方（Proposer）**：论证推荐方案的工程可行性、最小可逆改动路径、性能边界与落地步骤；
2. **反方（Skeptic / Red Team）**：专职挑刺，重点深挖并发竞态、跨平台兼容（Windows / WSL / macOS）、异常回滚死锁、权限越界与长期维护隐患，给出具体失效场景或更简替代方案。

### 阶段二：交叉反驳（Cross-Rebuttal）

提取第 1 轮正反双方的核心论点与关键质疑（剔除客套话），互换后发起第 2 轮 `prism_ask_model`：

- 要求双方**仅针对实质分歧点逐条回应**；
- 对对方指出的真实硬伤必须正面承认并给出修正补丁；对不成立的伪风险必须给出可验证的协议/代码依据予以驳回，严禁车轱辘话重复。

### 阶段三：主控收敛与实测核验（Convergence & Verification）

- 主控汇总「已达成共识 / 核心分歧裁决 / 方案修正项」，形成最终执行方案；
- **禁止盲信外部模型推论**：凡涉及本地 API 签名、Node.js 运行时行为、文件路径或配置字段的结论，主控必须通过读取本地源码与运行聚焦验证命令亲自核实后再落盘。

## 4. 安全与隐私零泄漏红线

- **严禁外发任何敏感凭据**：调用 `prism_ask_model` 前必须严格自检请求正文与代码上下文，**绝不得包含任何 API Key、OAuth Token、Cookie、密码、私钥、恢复码、个人邮箱、私有内网 IP/域名，以及 `.claude`、`.codex`、`.cc-switch`、`.ssh`、`.gnupg` 下的任何受保护凭据内容**；
- 确需展示配置结构时，必须先将敏感值替换为 `<REDACTED>` 占位符；
- 向用户汇报会诊或辩论结论时，显式注明本次实际调用的模型 ID 及其角色分工。
